# 后端开发顺序

确定日期：2026-10-14。

先完成传统后端的基本功能并走通业务流程，再接入 Agent。

1. **角色与登录鉴权**：区分负责人、普通运营员和园区点餐用户，完善登录与后端权限校验。
2. **运营人员管理**：负责人管理运营账号；普通运营员不能新增、编辑或禁用运营账号。负责人和普通运营员共用管理后台，按权限展示菜单和操作。
3. **分类、菜品、套餐**：实现分类与商品管理、套餐组成、起售停售和菜单查询。
4. **地址、购物车**：实现本人地址管理和购物车操作，校验用户归属。
5. **订单与支付**：实现下单、金额计算、库存事务、订单快照、支付与合法状态流转；采用模拟支付时明确标识。
6. **缓存、超时任务、通知、统计**：实现 Redis 缓存、超时订单关闭、订单通知和经营统计。
7. **Agent**：传统后端基本完成、普通页面能走通点餐与运营流程后，再将已有 Service 封装为工具，接入模型、工具调用及写操作确认，并复用已有权限规则。

当前阶段不提前搭建 Agent 框架。前端演示成功不作为真实后端功能完成的依据。
