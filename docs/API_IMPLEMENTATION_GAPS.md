# 接口基线与当前工程的实现差距

版本2026-10-16。本文区分“已经存在的代码”和“完整设计需要的持久化/前端能力”，防止把导入Apifox当成功能实现。本次不修改源代码、SQL或Nginx。

## 1. 已有代码与未验收边界

- 后端已有health、运营登录、当前运营ID、普通运营list、Web用户登录。运营拦截器检查JWT、账号存在/启用；manager通过EmployeePermissionService读数据库角色。
- 当前Web前端已接收accountRole，按角色隐藏人员菜单和限制路由，演示模式分两种运营；403读取后端msg。早期API_CONTRACT中“非2xx不读msg”的描述已经失效，本版已移除。
- 当前真实员工user接口、Agent、auth票据的完整拦截保护尚未实现。用户Controller存在不表示用户全链路鉴权已经完成。
- 最新代码存在不等于本次完成真实数据库、并发、微信/支付或LLM运行测试；本次只核对合同和静态文件。

## 2. 数据库需要补充但本次未执行的内容

当前学习表仍以[DATABASE_DESIGN.md](DATABASE_DESIGN.md)及infra/schema.sql为基础。旧脚本是13表学习版，不足以直接承载完整小程序与真支付。

| 范围 | 需要的持久化能力 | 约束/用途 |
| --- | --- | --- |
| employee角色 | account_role非空，默认OPERATOR | 当前Entity已有；旧infra/schema.sql尚未包含该列，实际库是否手动迁移需自行检查 |
| 微信身份 | 微信身份关联表或等价结构，user_id/appid/openid | 唯一(appid,openid)，同一user每appid最多一个身份；不返回身份密钥；不按手机号自动合并 |
| 微信用户建档 | Web用户名/密码可空或独立凭据表，资料与create_time | 微信用户没有Web密码；不能填固定默认密码；旧user非空username/password约束需迁移 |
| 改密/注销 | 凭据版本或失效时间、token jti/摘要拒绝列表 | 使旧凭证和WS可失效；不同角色ID命名空间分开 |
| 幂等请求 | 稳定键、身份、方法/路径、请求摘要、执行状态、业务结果、到期时间 | 唯一范围键，至少24小时；业务写入与完成记录可靠原子保存，不能只Redis先标记成功 |
| 支付记录 | 渠道、订单、商户支付号、prepay、微信交易号、整数分金额、状态和时间 | 商户号/微信交易号唯一、每订单唯一生效支付；补偿与关单不能仅依赖orders.pay_status |
| 退款记录 | 商户退款号、订单、支付记录、全额金额、状态、成功时间、原因 | 退款号唯一；失败重试沿用原号，跨日退款统计有事实来源 |
| 通知接收 | 供应商事件ID、验签后安全载荷、接收/消费状态、重试 | 通知事件唯一、先可靠落库再ACK；不存秘钥，敏感原始数据限定访问与保留期 |
| 订单催单 | urge_count、last_urged_at或独立催单记录 | 并发原子限制60秒/最多5次，不靠前端按钮禁用 |
| WS可靠补发 | 事务发件箱/事件记录（若需要可靠补发） | 普通提交后发送仍可能丢失，不能宣称恰好一次；HTTP恢复仍必须存在 |
| Agent确认 | 现有agent_action扩展或等价状态与版本记录 | 设计包含EXECUTING、失败原因、预期状态/版本，当前0～4状态字典需一致迁移；不随意重用旧整数含义 |
| 用户/统计索引 | user.create_time、订单时间/付款时间、退款成功时间、明细商品/订单关联 | 以实际SQL和执行计划检查；不编造优化效果 |

不直接混用temp中的24表脚本。它的menu_item/user_account和学习版dish/setmeal/user结构不同，不能先后叠加运行。后续使用明确版本迁移文件，保留已有学习数据，不因完善接口重建数据库。

## 3. 前端适配清单

| 当前入口 | 完整合同后的工作 |
| --- | --- |
| 人员列表数组 | 保留/list兼容；新页面调用/page并使用total，不在客户端假分页 |
| 新增人员初始密码 | 前端已增加initialPassword/确认密码及长度、UTF-8字节数、一致性校验；仅新增请求提交initialPassword，确认密码不提交，不增加角色输入。编辑资料不提交密码，后端校验和存储仍由后端负责 |
| 人员资料及状态共用PUT | 编辑不再携带无意修改的status；状态按钮走/{id}/status；登录名不可编辑 |
| 分类前端全量搜索 | 后续分页/page和专用status；原/list保留给下拉框 |
| 商品编辑/状态携带全对象 | 普通PUT不改stock，独立stock接口带expectedStock，状态按钮专用接口；图片使用上传URL |
| 商品合并目录 | 继续统一分页，不各取一页合并；组件分类禁用要计入不可售规则 |
| 现有Web登录/退出 | 登出接新logout；启动/403后可查询/me刷新角色；当前旧会话需重新登录获取角色 |
| 小程序尚无工程 | 使用本版用户接口，不复制一套后端；接wx.login、明确绑定、资料、地址、购物车、支付参数和WSS |
| 全量购物车 | 旧PUT保留；小程序优先增量/add、数量更新、删除、清空；每次点击独立键、重试复用 |
| 下单没有稳定键 | 为一次提交生成Idempotency-Key，失败重试复用，完成/新操作换键；缺键必须报错 |
| 旧模拟pay按钮 | 保留MOCK学习流程；WECHAT模式使用预支付/查单，不能把旧按钮当真实扣款 |
| 统计mock/文案 | 统一历史支付、退款现金、创建/支付人数和订单口径；旧趋势“创建订单”文案与支付口径不同需修正 |
| 工作台近7天待办 | 新/workbench待办统计全时间未完结，不漏旧订单 |
| 浏览器CSV导出 | 保留旧功能，增加服务器xlsx下载入口，不把CSV改后缀 |
| WS相对URL | 当前.env.production=/ws/orders但new URL无base；需同源解析并HTTPS→WSS、退出清理、按eventId去重 |
| Agent本地规则/卡片 | 后端真模型工具/持久确认；接会话和action查询，不把前端模板冒充LLM |

## 4. 内部实现不新增公开接口

公共字段自动填充、Redis查询回填及失效、订单超时/支付查单/退款补偿扫描、模型Tool Registry和工具执行器为内部组件。客户端不得传原始SQL、数据库表名、任意缓存键或任务名来要求执行。需要运维观测时使用受限日志/指标，不在本版业务API增加任意任务执行口。
